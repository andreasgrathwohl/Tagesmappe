# Frontstage — Umsetzungsplan, Übersicht

> **For agentic workers:** Dieses Dokument ist der gemeinsame Rahmen aller Teilpläne `01` bis `07` in
> diesem Ordner. Jeder Teilplan setzt es voraus. REQUIRED SUB-SKILL je Teilplan:
> superpowers:subagent-driven-development (empfohlen) oder superpowers:executing-plans.

**Goal:** Die erste Version (MVP) von Frontstage bauen – Tagesbegleiter für Lehrkräfte auf iPad und Mac.

**Architecture:** Native SwiftUI-App mit zwei Zielen (iPadOS, macOS) aus gemeinsamem Code, Projekt aus
XcodeGen; reine Logik im Swift-Paket `FrontstageKern`, Daten in SwiftData mit Spiegelung in die private
iCloud-Datenbank, Material nur als Verweis in die Ablage der Lehrkraft, keine eigenen Server.

**Tech Stack:** Swift 6 (strikt), SwiftUI, SwiftData + CloudKit, PDFKit, PencilKit, StoreKit 2, UIKit-Szenen
für den Zweitbildschirm, Swift Testing, XcodeGen, GitHub Actions (macOS-Runner).

**Spec:** `docs/PRD.md` (bindendes Glossar, FR/NFR/AK), `docs/adr/0001` bis `0008`,
`docs/ARCHITECTURE.md` (je Bereich), `DESIGN.md` (UI-1), Mockups unter `mockup/` als Veranschaulichung.

## Global Constraints

Jede Aufgabe jedes Teilplans schließt diese Zeilen ein.

- Mindestversion **iPadOS 26.0** und **macOS 26.0** (ADR-0007). Neuere Schnittstellen nur hinter `if #available(iOS 27, macOS 27, *)`.
- Sprachmodus **Swift 6**, `SWIFT_STRICT_CONCURRENCY = complete` (ADR-0008).
- Projekt nur über **`project.yml`** (XcodeGen); `*.xcodeproj` steht in `.gitignore` und wird nie eingecheckt (ADR-0008).
- Logik ohne Oberfläche gehört in **`Packages/FrontstageKern`**; das Paket importiert nur `Foundation` – kein SwiftUI, SwiftData, UIKit, AppKit (ADR-0008).
- Tests mit **Swift Testing** (`import Testing`, `@Test`, `#expect`); Kern-Tests laufen mit `swift test --package-path Packages/FrontstageKern`, App-Tests mit `xcodebuild test` im Simulator.
- **Kein Bau auf dem Entwicklungsrechner (Windows).** „Test ausführen“ heißt: im nächsten CI-Lauf. CI läuft nur bei Tags `v*` und per `workflow_dispatch`, nie bei jedem Push. Aufgaben eines Teilplans werden gesammelt und am Ende des Teilplans in **einem** CI-Lauf geprüft; vorher wird der Diff auf Compilerfehler durchgesehen.
- **SwiftData für iCloud-Spiegelung (ADR-0002):** kein `@Attribute(.unique)`, kein `#Unique`, jede Eigenschaft optional oder mit Vorgabewert, jede Beziehung optional.
- **Keine Server des Produkts (NFR-2):** keine Netzwerkverbindung außer Apple, Ablage-Anbieter, Microsoft (nach Anmeldung) und Schulmanager (wenn gewählt). Keine Analyse-, Absturz- oder Werbe-SDKs.
- **Zuordnen kopiert nie Dateien (FR-3.4):** Material ist immer ein Verweis; die App schreibt nie in die Ablage (ADR-0003, ADR-0006). Einzige Ausnahme: „Als PDF sichern“ der Tafel über den Teilen-Dialog des Systems (FR-12.4).
- **Zugangsdaten nur im Schlüsselbund des Geräts**, nicht gespiegelt (NFR-4).
- **Begriffe im Code folgen dem Glossar im PRD** (deutsche Bezeichner): `Stundenplan`, `StundenplanEintrag`, `Unterrichtsstunde`, `Material`, `Zuordnung`, `Ablage`, `Tagesansicht`, `Wochenvariante`, `Zeitraster`, `Ausfall`, `Vertretungsstunde`, `Klassenbildschirm`, `Tafel`, `Tafelbild`, `Stiftnotiz`, `Zweitbildschirm`. Kein Begriff, der dem Glossar widerspricht.
- **Oberflächentexte** nur über `Frontstage/Ressourcen/Localizable.xcstrings`, Deutsch als erste Sprache; Anrede: unpersönlich (kein „du“, kein „Sie“) – Platzhalter, bis eine Design-Runde den Wortlaut entscheidet.
- **Datenhygiene:** In Tests, Vorschauen und Beispielen nur neutrale Klassen (`7a`, `8a`, `8b`, `9c`, `6c`) und erfundene Materialnamen („Arbeitsblatt Vokabeln“); keine Personennamen, keine echten Schulen, keine Zugangsdaten.
- **Bundle-ID** `com.example.frontstage` als Platzhalter; die echte ID und das Team kommen in CI aus Secrets (`APPLE_TEAM_ID`, `BUNDLE_ID_PREFIX`), nie ins Repo.
- Commits: kleine Schritte, Nachricht englisch, Abschluss mit `Co-Authored-By`-Zeile.

## Gestaltung in den Aufgaben

- Jede Aufgabe, die Oberfläche berührt, trägt **`Design-Takt: keiner | Hauptstufe | voll`**.
  - `Hauptstufe`: vor dem Editieren den projektlokalen Skill `apple-design` laden (Apple-Richtlinien; benannte Ausnahme der Projekt-`CLAUDE.md` statt `impeccable`).
  - `voll`: zusätzlich nach der Aufgabe eine Prüfung mit `apple-design` als Prüfer.
- **Alle Gestaltungskategorien außer dem App-Icon (UI-1) sind offen.** Eine Aufgabe, die auf eine offene Kategorie stößt (Farbe, Dichte, Wortlaut, Zustandsdarstellung …), nimmt den **Systemstandard** von SwiftUI, nennt die Lücke in einer Zeile im Abschlussbericht und entscheidet nichts Eigenes. Beschlüsse entstehen nur über `/design:design-runde` mit einem Menschen und stehen in `DESIGN.md`.
- Die Design-Runden 1–10 laufen nach dem ersten lauffähigen Bildschirm (Ende Teilplan 04) – als eigene Aufgabe dort, nie unbeaufsichtigt.
- Die Mockups unter `mockup/` zeigen, **was** ein Bildschirm leisten muss, nicht **wie** er aussieht.

## Entscheidungen und Begründungen (aus dem Gespräch, nicht anderswo)

- Kern zuerst, Klassenbildschirm und Tafel danach (RISK-6) – Test mit Lehrkräften soll nicht warten.
- Mindestversion 26 statt 27 wegen älterer Lehrer-iPads; Preis: zwei Wege für den Zweitbildschirm (ADR-0007).
- XcodeGen statt eingechecktem `.xcodeproj` oder Tuist, weil auf Windows nur Text gepflegt werden kann (ADR-0008).
- Die App startet die AirPlay-Verbindung nicht selbst – das lässt das System nicht zu; sie erkennt sie und führt mit „So verbinden“ hin (FR-11.6). Verworfen: Videostrom über `AVRoutePickerView`.
- Zweitbildschirm zeigt nie die Tagesansicht; das Szenen-Zubehör (ab 27) wird an der **Hauptansicht** angemeldet, nicht erst in der Anzeige (Area anzeige).
- Stiftnotizen und Tafelbilder liegen in den App-Daten, nie in der Datei (ADR-0006); Stiftnotizen gehören zur Zuordnung (FR-6.1).
- Timer, Arbeitsform, Abdeckung und Zustand des Zweitbildschirms sind flüchtig, nicht gespeichert; Timer rechnet aus einem Endzeitpunkt (Area anzeige).
- Kein Countdown bis Stundenbeginn auf dem Klassenbildschirm (vom Nutzer verworfen); Hausaufgabe groß in den letzten fünf Minuten (FR-11.7).
- Kauf: Kern kostenlos, Klassenbildschirm und Tafel per Einmalkauf über StoreKit 2, geprüft auf dem Gerät; Material am Zweitbildschirm bleibt kostenlos; Schulmanager-Import immer kostenlos (FR-13, FR-13.1). Preis 14,99–19,99 €, genauer Wert beim App-Store-Eintrag.
- Schulmanager-Abfrage nur einmal je Morgen und auf Knopfdruck; kein Teilimport bei Fehlern (ADR-0004).
- Produktname „Frontstage“ ist intern; Markenprüfung offen (Q-31) – vor einem öffentlichen TestFlight-Link klären.

## Schnittstellen zwischen den Teilplänen (verbindlich)

Teilplan 01 erzeugt diese Typen in `Packages/FrontstageKern/Sources/FrontstageKern/`; alle anderen
Teilpläne benutzen genau diese Namen. Weitere Typen legt jeder Teilplan in seinem Interfaces-Block fest.

```swift
public struct Kalendertag: Hashable, Comparable, Codable, Sendable { public let jahr: Int; public let monat: Int; public let tag: Int }   // ohne Zeitzone
public enum Wochentag: Int, CaseIterable, Codable, Sendable { case montag = 1, dienstag, mittwoch, donnerstag, freitag, samstag, sonntag }
public enum Wochenvariante: String, Codable, Sendable { case a, b }
public struct KlassenName: Hashable, Codable, Sendable { public let normalisiert: String; public init(_ roh: String) }   // „8 b“, „08B“ → „8b“
public struct FachName: Hashable, Codable, Sendable { public let normalisiert: String; public let anzeige: String; public init(_ roh: String) }
public struct Uhrzeit: Hashable, Comparable, Codable, Sendable { public let stunde: Int; public let minute: Int }
public struct Zeitraster: Hashable, Codable, Sendable { public var stunden: [Int: ClosedRange<Uhrzeit>] }   // FR-1.2
public struct StundenplanEintragDaten: Hashable, Codable, Sendable { public var wochenvariante: Wochenvariante?; public var wochentag: Wochentag; public var stunde: Int; public var klasse: KlassenName; public var fach: FachName }
public struct StundenplanDaten: Codable, Sendable { public var anzahlWochenvarianten: Int; public var bezugswocheA: Kalendertag; public var zeitraster: Zeitraster; public var eintraege: [StundenplanEintragDaten] }
public struct UnterrichtsfreierZeitraum: Hashable, Codable, Sendable { public var von: Kalendertag; public var bis: Kalendertag; public var bezeichnung: String }
public struct UnterrichtsstundenSchluessel: Hashable, Codable, Sendable { public let datum: Kalendertag; public let klasse: KlassenName; public let fach: FachName; public let laufendeNummer: Int; public var text: String { get }; public init?(text: String) }   // ADR-0005
public enum Herkunft: String, Codable, Sendable { case hand, quelle }
public enum AbweichungDaten: Hashable, Codable, Sendable { case ausfall(UnterrichtsstundenSchluessel, Herkunft); case vertretungsstunde(datum: Kalendertag, stunde: Int, klasse: KlassenName, fach: FachName, Herkunft) }
public struct Unterrichtsstunde: Hashable, Sendable { public let schluessel: UnterrichtsstundenSchluessel; public let stunde: Int; public let zeit: ClosedRange<Uhrzeit>?; public let istVertretungsstunde: Bool; public let istAusfall: Bool; public let ausfallHerkunft: Herkunft? }
public enum Stundenplanrechner {
  public static func wochenvariante(fuer tag: Kalendertag, plan: StundenplanDaten) -> Wochenvariante?
  public static func unterrichtsstunden(am tag: Kalendertag, plan: StundenplanDaten, freieZeitraeume: [UnterrichtsfreierZeitraum], abweichungen: [AbweichungDaten]) -> [Unterrichtsstunde]   // zeitlich sortiert; leer an unterrichtsfreien Tagen
  public static func naechsteUnterrichtsstunde(nach schluessel: UnterrichtsstundenSchluessel, plan: StundenplanDaten, freieZeitraeume: [UnterrichtsfreierZeitraum], abweichungen: [AbweichungDaten], suchtageMax: Int = 28) -> UnterrichtsstundenSchluessel?   // gleiche Klasse und gleiches Fach, Ausfälle übersprungen (FR-3.3, FR-8)
}
public enum Klassenbildschirmphase: Hashable, Sendable { case vorBeginn(Unterrichtsstunde); case inStunde(Unterrichtsstunde); case letzteMinuten(Unterrichtsstunde); case keinUnterrichtMehr }   // FR-11.7
public enum KlassenbildschirmRechner { public static func phase(jetzt: Uhrzeit, stunden: [Unterrichtsstunde], letzteMinuten: Int = 5) -> Klassenbildschirmphase }
public struct ImportAbgleich: Sendable { public var neu: [StundenplanEintragDaten]; public var geaendert: [(alt: StundenplanEintragDaten, neu: StundenplanEintragDaten)]; public var konflikteVonHand: [(meine: StundenplanEintragDaten, quelle: StundenplanEintragDaten)]; public var entfallen: [StundenplanEintragDaten] }
public enum ImportAbgleicher { public static func vergleiche(vorhanden: [StundenplanEintragDaten], vonHandGeaendert: Set<StundenplanEintragDaten>, importiert: [StundenplanEintragDaten]) -> ImportAbgleich }   // AK-3
```

## Was nur am Gerät geprüft werden kann

Diese Abnahmekriterien lassen sich weder im Kern-Test noch im Simulator belegen; jeder Teilplan, der sie
berührt, endet mit einer **Geräte-Checkliste** (Schritte aus dem AK, Ergebnisfeld zum Abhaken), die ein
Mensch mit iPad, Mac und Apple TV abarbeitet: AK-5, AK-9, AK-11, AK-12 (Q-18), AK-17, AK-19, AK-21 (Q-16),
AK-23, AK-29, AK-35, AK-37, AK-40 (Sandbox-Konto), Q-22.
